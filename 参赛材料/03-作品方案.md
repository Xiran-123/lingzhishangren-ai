## 第3页：作品阐述（一）—— 背景与问题

### 行业背景
- 5G/6G 通信工程产业快速发展，对人才实践能力要求越来越高
- 传统通信教学"重理论、轻实践"，学生缺乏真实工程场景历练
- 学生不知道"学了能干什么""离岗位要求还差多远"

### 现有痛点

| 痛点 | 具体表现 |
|------|----------|
| **学习目标模糊** | 学生不了解通信岗位真实要求，不知道该重点学什么 |
| **实践机会稀缺** | 真实工程场景难以复现，实训成本高 |
| **反馈滞后** | 做完练习不知对错，能力提升看不见摸不着 |
| **教学盲区** | 教师无法掌握每个学生的薄弱点，"一刀切"教学 |

## 第4页：作品阐述（二）—— 解决思路

### 平台定位
面向通信工程专业学生与教师的一站式 **AI 驱动智能学习平台**，覆盖"学—练—评—导"全链路。

### 核心理念
- **以岗位胜任力为锚**：12维能力模型对标真实岗位要求，学生始终知道差距在哪
- **以 AI 为引擎**：AI 生成练习题、AI 排障分析、AI 个性化能力分析、AI 班级学情诊断
- **以场景为驱动**：沉浸式剧情演绎 + 工程实训 + 施压模拟，把真实岗位场景搬进课堂
- **以数据为依据**：对话、错题、学习记录全程留痕，AI 分析有据可依

## 第8页：技术方案（一）—— 系统架构

### 整体架构

```
┌─────────────────────────────────────────┐
│              前端（浏览器）               │
│   HTML/CSS/JS · SVG雷达图 · SSE流式接收  │
├─────────────────────────────────────────┤
│              后端（Flask）               │
│   路由 · 会话管理 · 数据持久化 · API网关  │
├──────────────┬──────────────────────────┤
│   数据层      │      AI 服务层            │
│  SQLite +    │  Kimi-K2.6               │
│  JSON文件     │  (SiliconFlow API)       │
│  /data挂载    │  SSE流式 + 非流式         │
└──────────────┴──────────────────────────┘
         │
    Docker 容器
  (Gunicorn + LibreOffice)
```

### 技术选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| 后端框架 | Flask | 轻量灵活，适合快速迭代 |
| 数据存储 | SQLite + JSON | 轻量级，无需额外数据库服务 |
| AI 模型 | Kimi-K2.6 | 长上下文能力强，中文理解优秀 |
| AI 调用 | SiliconFlow API | 支持 SSE 流式输出，延迟低 |
| 容器化 | Docker + Gunicorn | 一致部署，多线程并发 |
| 文件转换 | LibreOffice | PPT 转图片预览，无需商业组件 |
| 前端渲染 | 原生 JS + SVG | 零框架依赖，加载快 |

## 第9页：技术方案（二）—— AI 能力实现

### AI 调用流程

```
用户操作 → Flask 路由 → 组装 Prompt → SiliconFlow API → SSE流式返回 → 前端逐字渲染
```

### 四类 AI 能力

| 能力 | 输入数据 | 输出 |
|------|----------|------|
| AI 对话学习 | 学生消息 + 对话历史 | 知识解答、学习引导 |
| AI 个性化分析 | 15条对话 + 12维能力 + 10条错题 + 学习记录摘要 | 优势/不足/建议/评价 |
| AI 排障分析 | 故障现象描述 + 任务上下文 | 排查思路与建议 |
| AI 班级学情分析 | 全班12维平均 + 活跃度 + 学生摘要 | 共性问题/教学建议/重点关注 |

### 流式输出实现
- 后端：`Response(generator, content_type='text/event-stream')`
- 前端：`ReadableStream + TextDecoder` 逐字渲染 + 闪烁光标
- 性能优化：`max_tokens` 控制（个人1200/班级1500），Prompt 精简（对话30→15条）

## 第10页：技术方案（三）—— 数据模型与持久化

### 核心数据文件（/data 挂载目录）

| 文件 | 内容 |
|------|------|
| `students.json` | 学生信息、12维能力得分、对话历史、周任务进度 |
| `wrong_questions.json` | 错题本 |
| `learning_records.json` | 学习/实训记录 |
| `knowledge_base.json` | 知识库课件元数据 |
| `weekly_tasks.json` | 每周任务定义 |
| `job_positions.json` | 岗位招聘数据 |

### 12维能力模型

| 类别 | 维度 |
|------|------|
| 理论基础 | 信号与系统、电磁场与电磁波、通信原理 |
| 专业核心 | 5G移动通信、光纤通信、天线技术 |
| 工程实践 | 基站工程、网络规划、故障排查 |
| 工程伦理 | 职业素养、安全规范 |
| 综合素质 | 团队协作、沟通表达 |

### 数据安全
- API Key 通过 `api_key.local` 文件配置，不进代码仓库
- 部署脚本排除 `/data` 和 `/uploads`，数据不随部署丢失
- Cookie 会话认证，API Key 头部鉴权（`X_API_Key`）

## 第17页：创新之处

### 1. 全链路 AI 驱动
从"学（AI对话）→练（AI出题/排障）→评（AI个性化分析/班级诊断）→导（AI学习建议）"，AI 贯穿每个环节，非单一功能点。

### 2. 12维岗位胜任力模型
对标真实通信工程岗位要求，建立12维能力模型，聚合为5大类，学生始终知道"离岗位差多远""该补什么"。

### 3. SSE 流式 AI 分析
AI 分析弹窗逐字生成 + 闪烁光标，首字17秒到达，用户边看边等，体验感大幅提升。非传统的"干等→一次性弹出"。

### 4. 沉浸式场景驱动实训
不是做选择题，而是 AI 扮演同事/考官进行真实场景互动（故障排查、施压面试），把岗位场景搬进课堂。

### 5. 教师 AI 教学诊断
一键生成班级整体学情分析（共性问题/教学建议/重点关注），每个学生也可单独 AI 分析，辅助精准教学。

### 6. 全平台 AI 合规标识
所有 AI 生成内容均标注"✨ AI 生成内容"或"✨ 本报告由 AI 生成，仅供参考"，满足伦理与安全合规要求。
